# RecoverX — Non-Negotiable Recovery Realities & Limitations

## Core Principles
1. **Never fabricate scan results**: RecoverX never generates simulated items or inflated scan percentages.
2. **Never substitute thumbnails for originals**: If only a thumbnail is found, it is labeled as `Thumbnail Only` with its original dimension/size noted as unavailable or restricted.
3. **No magic claims on internal flash memory**:
   - Modern Android devices use ext4 or F2FS filesystems on top of eMMC/UFS flash storage.
   - Flash storage utilizes hardware-level Wear Leveling, Garbage Collection, and TRIM commands (`fstrim`).
   - When a file is unlinked and deleted in userland, blocks are quickly marked as discarded. Once TRIM executes, blocks return zeros when read.
   - File-based encryption (FBE) encrypts files with distinct keys. When a key is evicted or a file inode cleared, raw bytes are cryptographically indecipherable.
4. **Legitimate Recovery Vectors in RecoverX**:
   - **Accessible Trash/Recycle Bins**: Many Android implementations (OEM Gallery, MediaStore `IS_TRASHED` flag on API 30+) retain deleted items for 30 days before permanent purging.
   - **Alternate Copies & Backups**: Discovering copies in sync folders, download folders, messaging app sent directories, or external SD cards.
   - **Accessible Cached Media**: Thumbnails and downscaled previews generated by system media scanners or gallery apps (`.thumbnails`, cache directories).
   - **MIME & Extension Mismatches**: Files renamed with `.tmp`, `.dat`, or missing extensions whose magic bytes confirm them as genuine JPEG, PNG, MP4, PDF, or ZIP files.
   - **Corrupted / Truncated Stream Recovery**: Identifying salvageable headers or streams where partial extraction is possible.
   - **External Storage / FAT32 / exFAT**: SD cards without active TRIM where unallocated sectors or deleted directory table entries can be inspected when mounted.
